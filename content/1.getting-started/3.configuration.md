## Overview

After publishing the configuration file with `php artisan vendor:publish --tag=tapix-config`, you will find it at `config/tapix.php`. This page documents every available option grouped by purpose.

## File Upload

### `max_file_size`

Maximum upload file size in bytes. Files exceeding this limit are rejected before processing begins.

- **Default:** `52428800` (50 MB)

```php [config/tapix.php]
'max_file_size' => 50 * 1024 * 1024,
```

Adjust this value based on your server's `upload_max_filesize` and `post_max_size` PHP settings. The lower of the three values applies.

### `max_rows`

Maximum number of rows allowed in a single import file. The wizard rejects files that exceed this count during the upload step.

- **Default:** `100000`

```php [config/tapix.php]
'max_rows' => 100_000,
```

For very large imports, consider increasing this alongside appropriate queue timeout values.

## Queue Processing

### `chunk_size`

Number of rows loaded and processed at a time. `ExecuteImportJob` works through the import in chunks of this size inside a single job, and uploads insert rows into the import store in chunks of this size.

- **Default:** `500`

```php [config/tapix.php]
'chunk_size' => 500,
```

Lower values reduce peak memory. Higher values mean fewer queries.

### `queue`

Queue configuration for import processing jobs. All queue-related settings are grouped under the `queue` key.

```php [config/tapix.php]
'queue' => [
    'validation' => env('TAPIX_QUEUE_VALIDATION', 'default'),
    'execution' => env('TAPIX_QUEUE_EXECUTION', 'default'),
    'timeout' => 600,
    'tries' => 3,
    'backoff' => [10, 30],
],
```

### `queue.validation` / `queue.execution`

Queue names (not connections) for validation and execution jobs. Tapix uses separate queues for each stage, allowing you to prioritize or isolate them. Jobs are pushed to your application's default queue connection.

- **Default:** `'default'`

If you change these, your worker must listen on the new queue names, or the jobs will never run:

```env [.env]
TAPIX_QUEUE_VALIDATION=imports-validation
TAPIX_QUEUE_EXECUTION=imports
```

```bash [Terminal]
php artisan queue:work --queue=imports-validation,imports
```

### `queue.timeout`

Maximum execution time in seconds for each chunk processing job. If a job exceeds this duration, the queue worker terminates it.

- **Default:** `600` (10 minutes)

Your queue connection's `retry_after` value must exceed `queue.timeout` to prevent overlapping job execution. For example, if `timeout` is 600, set `retry_after` to at least 630.

::note
The `retry_after` value is configured on your queue connection in `config/queue.php`, not in the Tapix configuration. Ensure it exceeds the `timeout` for whichever connection Tapix uses.
::

### `queue.tries`

Maximum number of attempts for each chunk processing job before it is marked as failed.

- **Default:** `3`

### `queue.backoff`

Delay in seconds between retry attempts. Accepts an integer for a fixed delay or an array for progressive backoff.

- **Default:** `[10, 30]`

With the default value, the first retry waits 10 seconds and the second retry waits 30 seconds.

### `review.stall_timeout_seconds`

How long the wizard waits for validation progress before showing the "no background worker" error. Not in the published config by default. Add it if your queue is often busy.

- **Default:** `20`

```php [config/tapix.php]
'review' => [
    'stall_timeout_seconds' => 60,
],
```

## Import Store

### `store.path`

Directory path where Tapix stores per-import SQLite files. Each import gets its own SQLite database for row storage, which allows fast row-level operations without impacting your main database.

- **Default:** `storage_path('app/tapix')`

```php [config/tapix.php]
'store' => [
    'path' => storage_path('app/tapix'),
],
```

### `store.read_cache_path`

Local directory where workers cache read-only copies of import stores downloaded from `store.remote_disk`. Only used when a remote disk is configured. `tapix:cleanup` prunes it.

- **Default:** `storage_path('framework/cache/tapix')`
- **Environment variable:** `TAPIX_READ_CACHE_PATH`

### `store.lock`

When `store.remote_disk` is set, writes to an import store are serialized with a cache lock. This requires a lock-capable cache driver (`redis`, `database`, `memcached`, or `dynamodb`).

```php [config/tapix.php]
'store' => [
    'lock' => [
        'ttl' => 120,
        'block_seconds' => [
            'job' => 10,
        ],
    ],
],
```

| Key | Default | Description |
|-----|---------|-------------|
| `ttl` | `120` | Seconds before a held lock expires. |
| `block_seconds.job` | `10` | Seconds a job waits for the lock before throwing `WriteLockException`. |

### `store.remote_disk`

When running queue workers on multiple servers, set this to a shared filesystem disk (e.g., S3) so workers can access import data across machines. The SQLite file is uploaded to this disk after the review step and downloaded by the worker before execution.

- **Default:** `null` (local filesystem only)
- **Environment variable:** `TAPIX_STORE_DISK`

```php [config/tapix.php]
'store' => [
    'remote_disk' => env('TAPIX_STORE_DISK'),
],
```

## Database

### `table_names`

Explicit table names for Tapix database tables. This prevents naming conflicts with your application's existing tables.

- **Default:**

```php [config/tapix.php]
'table_names' => [
    'imports' => 'tapix_imports',
    'failed_import_rows' => 'tapix_failed_import_rows',
],
```

Override these to use custom table names:

```php [config/tapix.php]
'table_names' => [
    'imports' => 'my_imports',
    'failed_import_rows' => 'my_failed_import_rows',
],
```

::warning
Changing table names after running migrations will cause Tapix to look for tables that do not exist. You must manually rename the existing tables in your database or run a fresh migration.
::

## Multi-Tenancy

The `tenant` configuration group controls multi-tenant scoping. When enabled, all imports are automatically scoped to the current tenant. See the [Multi-Tenancy](/features/multi-tenancy) guide for full details.

### `tenant.enabled`

Enable or disable tenant scoping.

- **Default:** `false`

```php [config/tapix.php]
'tenant' => [
    'enabled' => false,
],
```

### `tenant.column`

The database column name used to store the tenant identifier on import records.

- **Default:** `'tenant_id'`

```php [config/tapix.php]
'tenant' => [
    'column' => 'tenant_id',
],
```

### `tenant.strict`

When enabled, queries on tenant-scoped models return zero results if no tenant context has been set. This prevents accidental data leakage across tenants. See [Strict Mode](/features/multi-tenancy#strict-mode).

- **Default:** `true`

```php [config/tapix.php]
'tenant' => [
    'strict' => true,
],
```

### `tenant.model`

The fully qualified class name of your tenant model. Used by adapters (e.g., the Relaticle adapter) that need to resolve tenant model instances.

- **Default:** `null`

```php [config/tapix.php]
'tenant' => [
    'model' => null,
],
```

## Class Swapping

Tapix lets you swap the default models and job classes with your own implementations using the `Tapix` facade. Call these methods in your service provider's `boot()` method.

### Models

```php [app/Providers/AppServiceProvider.php]
use Tapix\Core\Tapix;

Tapix::useImportModel(\App\Models\CustomImport::class);
Tapix::useFailedRowModel(\App\Models\CustomFailedImportRow::class);
```

Custom model classes should extend the originals. Tapix resolves model classes through `Tapix::importModel()` and `Tapix::failedRowModel()`, ensuring all internal queries use your custom models.

### Jobs

```php [app/Providers/AppServiceProvider.php]
use Tapix\Core\Tapix;

Tapix::useExecuteJob(\App\Jobs\CustomExecuteImportJob::class);
Tapix::useValidateJob(\App\Jobs\CustomValidateImportJob::class);
Tapix::useResolveMatchesJob(\App\Jobs\CustomResolveMatchesJob::class);
```

Job classes are resolved via `Tapix::executeJobClass()`, `Tapix::validateJobClass()`, and `Tapix::resolveMatchesJobClass()`.

### Custom Fields Adapter

```php [app/Providers/AppServiceProvider.php]
use Tapix\Core\Tapix;

Tapix::useCustomFieldsAdapter(\App\Imports\MyCustomFieldsAdapter::class);
```

When `relaticle/custom-fields` is installed, the adapter is auto-discovered. Use this method to override auto-discovery or register a custom adapter. See the [Custom Fields](/features/custom-fields) guide for details.

## File Readers

### `readers`

A map of file extensions to reader classes. Tapix uses these to determine how to parse an uploaded file based on its extension.

- **Default:**

```php [config/tapix.php]
'readers' => [
    'csv' => \Tapix\Core\Importing\Readers\CsvReader::class,
    'txt' => \Tapix\Core\Importing\Readers\CsvReader::class,
    'xlsx' => \Tapix\Core\Importing\Readers\XlsxReader::class,
],
```

You can register custom reader classes for additional file formats. Each reader must implement the `Tapix\Core\Contracts\FileReader` interface. See the [Custom Readers](/features/file-formats) section for details.

## Notifications

### `notifications.enabled`

Whether to send a notification when an import completes (or fails).

- **Default:** `true`

```php [config/tapix.php]
'notifications' => [
    'enabled' => true,
],
```

### `notifications.class`

The notification class dispatched when an import finishes. You can replace this with a custom notification to change the message content, channels, or recipients.

- **Default:** `Tapix\Core\Notifications\ImportCompletedNotification::class`

```php [config/tapix.php]
'notifications' => [
    'class' => \Tapix\Core\Notifications\ImportCompletedNotification::class,
],
```

The custom notification class receives the completed `Import` model as a constructor argument.

## Cleanup

### `cleanup_after_days`

Number of days to retain completed import records and their associated temporary data. The `tapix:cleanup` scheduled command deletes records older than this value.

- **Default:** `30`

```php [config/tapix.php]
'cleanup_after_days' => 30,
```

To enable automatic cleanup, schedule the command in your application:

```php [routes/console.php]
use Illuminate\Support\Facades\Schedule;

Schedule::command('tapix:cleanup')->daily();
```

## Importer Discovery

### `importer_directories`

An array of directory paths where Tapix looks for importer classes. The `discoverImporters()` method on `TapixPlugin` scans these directories to register importers automatically.

- **Default:** `[app_path('Importers')]`

```php [config/tapix.php]
'importer_directories' => [
    app_path('Importers'),
],
```

Add additional directories if you organize importers across multiple locations, such as within domain-specific folders.

### `importer_namespace`

The PHP namespace corresponding to the importer directories. Importer discovery uses it to turn discovered file paths into class names. `make:tapix-importer` always writes to `app/Importers`.

- **Default:** `'App\\Importers'`

```php [config/tapix.php]
'importer_namespace' => 'App\\Importers',
```

## Routes

Tapix registers its own routes for handling file uploads and import progress. The route settings are defined in `config/tapix.php`:

```php [config/tapix.php]
'routes' => [
    'enabled' => true,
    'prefix' => 'imports',
    'domain' => null,
    'middleware' => ['web', 'auth'],
],
```

| Key | Default | Description |
|-----|---------|-------------|
| `enabled` | `true` | Set to `false` to disable route registration entirely. |
| `prefix` | `'imports'` | URL prefix for all Tapix routes (e.g. `/imports/...`). |
| `domain` | `null` | Restrict routes to a specific subdomain. |
| `middleware` | `['web', 'auth']` | Middleware applied to all routes. |

### Disabling routes

You can also disable routes programmatically in a service provider:

```php [app/Providers/AppServiceProvider.php]
use Tapix\Core\Tapix;

public function boot(): void
{
    Tapix::disableRoutes();
}
```

When `TapixPlugin` is registered in a Filament panel, routes are disabled automatically since Filament manages its own routing.

### Available endpoints

| Method | Route | Description |
|--------|-------|-------------|
| GET | `{prefix}/tapix/imports/{import}/failed-rows/download` | Download failed import rows (signed URL, route name `tapix.download-failed-rows`). |

## Example CSV Templates

### `example_csv.enabled`

Whether the upload step shows a "Download Template" button that generates a CSV file with field keys as headers and `->example()` values as the first row. Users can download this template, fill it in, and upload it back -- the headers are guaranteed to auto-map correctly.

- **Default:** `true`

```php [config/tapix.php]
'example_csv' => [
    'enabled' => true,
],
```

Set to `false` to globally hide the download button for all importers. Individual importers can also opt out by overriding `hasExampleCsv()` -- see [Defining Importers](/importers/defining-importers#hasexamplecsv-bool).

### `example_csv.required_marker`

Suffix appended to required-field headers in the template (e.g. `name *`). The marker is stripped automatically when the filled-in template is uploaded. Set to `''` to disable.

- **Default:** `' *'`

### `example_csv.use_labels_as_headers`

Use each field's label (e.g. `Contract Start Date`) instead of its key (e.g. `contract_start_date`) as the template header. Both still auto-map on upload.

- **Default:** `false`

## Publishable Assets

Tapix makes several asset groups available for publishing:

| Tag | Description |
|-----|-------------|
| `tapix-config` | Configuration file (`config/tapix.php`, plus `config/tapix-inertia.php` with `tapix/inertia`) |
| `tapix-migrations` | Database migration files |
| `tapix-views` | Livewire Blade view templates (for UI customization) |
| `tapix-core-translations` | Core validation and error messages (`lang/vendor/tapix-core`) |
| `tapix-translations` | Livewire wizard UI strings (`lang/vendor/tapix`) |

```bash [Terminal]
# Publish config (included in standard installation)
php artisan vendor:publish --tag=tapix-config

# Publish migrations (only if you need to customize them)
php artisan vendor:publish --tag=tapix-migrations

# Publish views (only if you need to customize the UI)
php artisan vendor:publish --tag=tapix-views
```
