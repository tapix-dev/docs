Tapix exposes lifecycle hooks that let you run custom logic at specific points during the import process. These hooks are defined as methods on your importer class.

## Hook Overview

The import lifecycle flows through these stages:

1. **Access check** -- `canImport()` determines whether the user can access the importer.
2. **Pre-import** -- `beforeImport()` runs once before processing begins.
3. **Pre-validation** -- `beforeValidation()` runs before column validation starts.
4. **Per-row processing** -- For each row: `beforeFill` > `prepareForSave()` > `afterFill` > `beforeSave` > `beforeCreate`/`beforeUpdate` > save > `afterCreate`/`afterUpdate` > `afterSave`.
5. **Post-import** -- `afterImport()` runs once after all rows are processed.

Import-level hooks (`beforeImport`, `beforeValidation`, `afterImport`) receive the `Import` model. Per-row hooks (`beforeFill` through `afterSave`) take **no arguments**. They read and modify row state through properties on the importer instead. `prepareForSave()` is the one per-row hook with parameters.

## Hook Reference

### `canImport(): bool`

Controls access to the importer. Called before the import wizard is shown. Return `false` to prevent the user from accessing this importer.

Defaults to `true`.

```php [app/Importers/ContactImporter.php]
public function canImport(): bool
{
    return auth()->user()->hasPermissionTo('import contacts');
}
```

### `beforeImport(Import $import): void`

Called before rows are processed. Use this to set up state or log the start of an import.

::note
`beforeImport()` also runs before match resolution during the review step, so it can be called more than once per import and in different queue workers. Keep it idempotent.
::

```php [app/Importers/ContactImporter.php]
use Tapix\Core\Models\Import;

public function beforeImport(Import $import): void
{
    logger()->info("Starting import #{$import->id} with {$import->total_rows} rows");
}
```

### `beforeValidation(Import $import): void`

Called before column validation starts. Use this to prepare validation context or modify import settings before values are checked.

```php [app/Importers/ProductImporter.php]
use Tapix\Core\Models\Import;

public function beforeValidation(Import $import): void
{
    // Pre-load lookup tables for custom validation rules
    cache()->put(
        "import:{$import->id}:valid-codes",
        ProductCode::pluck('code')->toArray(),
        now()->addHour(),
    );
}
```

### `prepareForSave(array $data, ?Model $existing, array &$context): array`

Transforms row data right before it is written to the model. Optional: define it only if you need it. Runs for every row after `beforeFill`.

Parameters:

- **`$data`** -- The mapped, cast row data as a key-value array. `id` has already been removed.
- **`$existing`** -- The matched model when updating an existing record, or `null` when creating.
- **`$context`** -- Import metadata: `tenant_id` (when multi-tenancy is enabled) and `creator_id` (the user who started the import).

Return the modified array. Tapix then:

- keeps only importer field keys, relationship foreign keys, the tenant column, `creator_id`, and `creation_source`. Any other key you add is dropped,
- drops `null` values, so a blank cell never overwrites an existing value,
- on updates, drops the tenant column, `creator_id`, and `creation_source`.

```php [app/Importers/ContactImporter.php]
use Illuminate\Database\Eloquent\Model;

public function prepareForSave(array $data, ?Model $existing, array &$context): array
{
    $data['email'] = strtolower($data['email'] ?? '');
    $data['creator_id'] = $context['creator_id'];

    return $data;
}
```

To set attributes that aren't import fields (e.g. a default `status`), assign them on `$this->record` in `beforeSave` or `beforeCreate` instead.

## Per-Row Hooks

Per-row hooks are parameterless methods on your importer. Tapix calls each one only if it exists.

::warning
Don't declare parameters on these methods. Tapix calls them with no arguments, so `beforeSave(Model $model, array $data)` throws an `ArgumentCountError`.
::

### Available State

| Property | Type | Description |
|----------|------|-------------|
| `$this->data` | `array` | The current row's mapped data. |
| `$this->record` | `?Model` | The existing model on updates. On creates it is `null` until just before `beforeSave`, when it becomes the new, unsaved model. |
| `$this->context` | `array` | `tenant_id` and `creator_id`. |
| `$this->isCreating` | `bool` | `true` when the row creates a record, `false` when it updates one. |

### Execution Order

1. **`beforeFill`** -- `$this->data` holds the mapped row. Changes here are passed to `prepareForSave()` and saved.
2. **`prepareForSave()`** -- see above.
3. **`afterFill`** -- Runs after the attributes are prepared. Changing `$this->data` here no longer affects what is saved. Set `$this->skipSave` here to skip the row.
4. **`beforeSave`** -- `$this->record` is the model about to be saved. Set attributes on it directly. These are kept even if they aren't import fields.
5. **`beforeCreate`** or **`beforeUpdate`**
6. *The record is saved.*
7. **`afterCreate`** or **`afterUpdate`**
8. **`afterSave`** -- `$this->record` is saved and has a primary key.

All of steps 1--8 run inside one database transaction per row. If any hook throws, the row is rolled back and recorded as a failed row.

```php [app/Importers/ContactImporter.php]
use Illuminate\Support\Str;

final class ContactImporter extends BaseImporter
{
    // model() and fields() omitted

    public function beforeFill(): void
    {
        if (isset($this->data['email'])) {
            $this->data['email'] = strtolower($this->data['email']);
        }
    }

    public function beforeCreate(): void
    {
        $this->record->uuid = (string) Str::uuid();
        $this->record->status = 'pending';
    }

    public function afterSave(): void
    {
        ContactImported::dispatch($this->record);
    }

    public function afterUpdate(): void
    {
        logger()->info("Contact {$this->record->getKey()} updated via import");
    }
}
```

### `afterImport(Import $import): void`

Called once after all rows have been processed. Use this for summary actions like updating caches or running aggregate calculations. The `Import` model exposes `total_rows`, `created_rows`, `updated_rows`, `skipped_rows`, and `failed_rows`.

```php [app/Importers/ContactImporter.php]
use Tapix\Core\Models\Import;

public function afterImport(Import $import): void
{
    logger()->info("Import #{$import->id} complete", [
        'created' => $import->created_rows,
        'updated' => $import->updated_rows,
        'failed' => $import->failed_rows,
    ]);
}
```

::tip
A completion notification is sent automatically. See [Notifications](/features/notifications).
::

## Skipping Database Saves

Set `$skipSave` to skip persisting a row. The row is counted as skipped and `beforeSave` onwards does not run. `BaseImporter` already includes the `HasSkipSave` trait, so just set the property. Don't `use` the trait again.

For dispatch-only importers that never save (e.g. triggering an API call per row):

```php [app/Importers/WebhookDispatchImporter.php]
use Illuminate\Support\Facades\Http;
use Tapix\Core\Importing\BaseImporter;

final class WebhookDispatchImporter extends BaseImporter
{
    protected bool $skipSave = true;

    // model() and fields() omitted

    public function afterFill(): void
    {
        Http::post('https://webhook.example.com', $this->data);
    }
}
```

To skip rows conditionally, assign it on every row. `$skipSave` is **not** reset between rows:

```php
public function afterFill(): void
{
    $this->skipSave = ($this->data['status'] ?? null) === 'archived';
}
```

## Matching Existing Records

### `matchableFields(): array`

Defines which fields are used to match imported rows against existing records in the database. When a match is found, the existing record is updated rather than creating a duplicate.

Defaults to `[MatchableField::id()]`.

```php [app/Importers/ContactImporter.php]
use Tapix\Core\Data\MatchableField;

public function matchableFields(): array
{
    return [
        MatchableField::id(),
        MatchableField::email('email'),
        MatchableField::name(),
    ];
}
```

## Practical Example

Combining multiple hooks in a single importer:

```php [app/Importers/ContactImporter.php]
namespace App\Importers;

use App\Events\ContactImported;
use App\Models\Contact;
use Illuminate\Database\Eloquent\Model;
use Illuminate\Support\Str;
use Tapix\Core\Fields\ImportField;
use Tapix\Core\Importing\BaseImporter;
use Tapix\Core\Models\Import;

final class ContactImporter extends BaseImporter
{
    public function model(): string
    {
        return Contact::class;
    }

    public function fields(): array
    {
        return [
            ImportField::make('name')->required(),
            ImportField::make('email')->required(),
        ];
    }

    public function canImport(): bool
    {
        return auth()->user()->can('import contacts');
    }

    public function beforeImport(Import $import): void
    {
        logger()->info("Starting contact import #{$import->id}");
    }

    public function prepareForSave(array $data, ?Model $existing, array &$context): array
    {
        $data['email'] = strtolower($data['email'] ?? '');

        return $data;
    }

    public function beforeCreate(): void
    {
        $this->record->uuid = (string) Str::uuid();
    }

    public function afterSave(): void
    {
        ContactImported::dispatch($this->record);
    }

    public function afterImport(Import $import): void
    {
        logger()->info("Contact import #{$import->id} created {$import->created_rows} rows");
    }
}
```
